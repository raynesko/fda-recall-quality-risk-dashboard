# T5.1.1 - Design and pre-register the risk score and flag rule

**Sub-epic:** SE5 Risk Scoring & Backtest Validation  |  **Story S5.1:** As a QA lead, I want a transparent risk score that flags rising failure modes and has been backtested against naive baselines, so that I can trust (or challenge) its flags.

## Description
Components (rank-percentile within product_type): momentum (trailing-12m vs prior-12m log rate ratio with 0.5 pseudo-count); severity (Class I share, trailing 24m); signal (count of SPC rule violations in trailing 6m); breadth (1 - share of the largest single firm; penalizes single-firm artifacts); volume (log trailing-12m events). Default weights 0.35/0.25/0.20/0.10/0.10 chosen a priori and justified in the doc. Flag = top-quartile score AND momentum > 0 AND trailing-12m events >= 10. Write the evaluation plan and success criteria in the doc and commit it BEFORE running T5.1.2 (pre-registration).

## Acceptance criteria
- [x] risk-score.md contains formulas, weights, justification, flag rule, and a dated 'pre-registration' section committed before T5.1.2 starts
- [x] Weights sum to 1.0 (test)
- [x] Toy-data score matches a hand-computed value (test)
- [x] Score table by category x month x product_type is produced; each row names its top contributing component
- [x] Minimum-volume guard demonstrably suppresses a flag in a small-count test case
