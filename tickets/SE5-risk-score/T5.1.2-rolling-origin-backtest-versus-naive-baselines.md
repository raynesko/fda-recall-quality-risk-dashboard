# T5.1.2 - Rolling-origin backtest versus naive baselines

**Sub-epic:** SE5 Risk Scoring & Backtest Validation  |  **Story S5.1:** As a QA lead, I want a transparent risk score that flags rising failure modes and has been backtested against naive baselines, so that I can trust (or challenge) its flags.

## Description
Origins every 6 months from 2016-06 to latest minus 12 months. At each origin compute scores using ONLY data up to the origin; outcome = next-12-month log change in event count and Class I share, per category x product_type. Baselines: B1 rank by trailing-12m volume; B2 momentum only; B3 random (permutation). Use non-overlapping 12-month-spaced origins for inference and block bootstrap by year; 6-monthly origins are descriptive only. Be explicit about regression to the mean.

## Acceptance criteria
- [x] Leakage test: score at an origin is identical when all rows after the origin are deleted
- [x] Reported: Spearman rho (score vs outcome) with block-bootstrap 95% CI; precision@3 vs B1/B2/B3 with permutation p-values
- [x] TARGET (not an achieved result): precision@3 exceeds best baseline by >= 0.15 and rho CI excludes 0. If missed, reports/backtest.md says so plainly and the README framing changes accordingly
- [x] Number of origins and units is stated next to every statistic
- [x] All numbers recorded through record_metric with label 'achieved'
