# T2.1.3 - Clean data, dedupe to recall-event level, build metrics helper

**Sub-epic:** SE2 Data Acquisition & Modeling  |  **Story S2.1:** As an analyst, I want a reproducible ingestion and cleaning pipeline from openFDA, so that anyone can rebuild the dataset from source and trust the counts.

## Description
Produce a product-level table (one row per recall_number) and an event-level table (one row per event_id). Document the rule used when one event has several distinct reason texts (default: keep the most frequent, tie -> longest; keep all variants in a list column). Also implement results/metrics.json helper `record_metric(key, value, source, label)` - the ONLY allowed way numbers reach the README/resume. Compute reporting-lag stats (recall_initiation_date -> report_date).

## Acceptance criteria
- [x] All non-null date strings parse to datetime (0 parse failures asserted in test)
- [x] recall_number is unique in the product table (asserted) and event_id is unique in the event table (asserted)
- [x] Classification values are in {Class I, Class II, Class III}; anything else is counted and listed in the data-quality report
- [x] reports/data_quality.md has: product vs event counts per product_type, date range, null rate per column, duplicate/text-variant counts, and lag distribution (median, P75, P90 days)
- [x] `record_metric` writes to results/metrics.json with value, source script, UTC timestamp and a `target` vs `achieved` label; unit test passes
- [x] `pytest tests/test_clean.py` passes
