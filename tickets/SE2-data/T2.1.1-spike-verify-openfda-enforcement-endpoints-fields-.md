# T2.1.1 - Spike: verify openFDA enforcement endpoints, fields, limits and bulk download

**Sub-epic:** SE2 Data Acquisition & Modeling  |  **Story S2.1:** As an analyst, I want a reproducible ingestion and cleaning pipeline from openFDA, so that anyone can rebuild the dataset from source and trust the counts.

## Description
TIME BOX 1.5h. Verify against live openFDA docs and a real query - do not assume. Check drug/enforcement and food/enforcement (and note whether device/enforcement exists but is out of scope). Decide bulk-download vs API pagination.

## Acceptance criteria
- [x] Notes list the exact endpoint URLs and the query used to obtain total record count and min/max report_date for each endpoint, with retrieval date and the raw numbers
- [x] Notes list available fields; confirm presence/absence of: recall_number, event_id, reason_for_recall, classification, report_date, recall_initiation_date, center_classification_date, status, recalling_firm, state, product_type, voluntary_mandated, product_description, distribution_pattern, product_quantity
- [x] Rate limits (with and without API key), page-size and skip limits are stated with the URL they came from
- [x] Bulk download page (open.fda.gov/data/downloads) checked; file names and sizes recorded, or its absence recorded
- [x] A decision (bulk vs API) is written with rationale
- [x] Notes state whether biologics (CBER) recalls appear and whether the data has an update cadence (e.g., weekly)
